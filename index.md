CS-499-12675-M01

Professional Self-Assessment

Tyler Webb

October 25, 2026

I started the Computer Science program at SNHU in the summer of 2023, and I was already working in software when I enrolled. I got my first job in the field as a product owner. I had a lot of business domain knowledge at the time, but very little technical knowledge. I skilled up from there and moved into my current role as a Software Development Manager, all before finishing my degree. Today, I lead a team of three developers and a product owner. I am responsible for the development side of our application and for integrating that software into the business. This program filled in the technical foundation behind the work I was already doing, and this ePortfolio shows that foundation in practice.

The biggest change the program made is that it gave me a growth mindset. I have been able to use what I’m learning in my day-to-day job, and that has made me a better and more effective manager. My career goal is to keep. Moving from the management and planning side toward a director or CTO role. Getting there means understanding the technical decisions my team makes well enough to evaluate and guide them. I plan to keep learning after this degree to keep up with current trends and to stay sharp. What sets me apart is my ability to skill up. I have already gone from a business role to leading a development team, and this program is a big part of how I did it.

Most of my experience collaborating in a team environment comes from work. The program did not include group projects, and the discussion boards were the main point of contact with other students. At work, I lead three developers and a product owner, so collaboration is part of every day. I am responsible for both the development work and how that work fits into the rest of the business. The CS 499 code review is the closed example from the program. I walked through existing code, identified weaknesses using a code review checklist, and explained my planned changes for an audience of peers or a manager.

Communicating with stakeholders is a core part of my role since I’m responsible for integrating our software into the business and not just building it. The program gave me patience doing this in writing. For example, in CS-255 I created a system design document and client presentation for DriverPass, a driving school. The presentation explained the system’s requirements, security, and limitations in plain language for a client without a technical background. In DA-220, I wrote a report for a product manager that summarized an analysis of return merchandise authorizations. The report presents the findings for readers who were not technical and pointed out flaws in the data and ways the queries could be improved.

CS-300 is where I worked most directly with data structures and algorithms. I designed a course advising program in pseudocode for a vector, a hash table, and a binary search tree, then compared the runtime of each. I recommended the binary search tree since it has an O(log n) average search time, and an in-order traversal prints the courses in sorted order without a separate sort step. I then built the program in C++. It loads course data from a CSV file into a binary search tree and validates that every prerequisite exists before adding a course. In CS-370, I trained a pirate agent to find treasure in a maze using deep Q-learning with experience replay. The agent reaches a 100%-win rate at epoch 441.

My database experience covers both relational and document databases. In DAD-220, I created a MySQL database schema from an entity relationship diagram, imported data from CSV files, and wrote queries with joins and WHERE clauses to analyze it. In CS-340, I wrote a Python module that creates and reads records in MongoDB. CS-465 brought these pieces together when I built Travlr, a travel booking web application on the MEAN stack of MongoDB, Express, Angular, and Node.js. It used Mongoose schemas with required fields to model trip and user data, a REST API between the front end and the database, and a single page application for administrators.

The program also gave me hand-on practice finding and fixing security issues. In CS-305, I completed a vulnerability assessment for Artemis Financial, a financial consulting company. I reviewed the code manually, ran a dependency check that found outdated libraries with known vulnerabilities, and wrote a mitigation plan to update them and retest afterward. I also recommended TLS encryption with a cipher of at last 128 bits for traffic between the server and its clients. In CS-465, I secured the Travlr API by hashing passwords with a unique salt and required a JSON Web Token that expires after one hour on every route that changes trip data. In CS-370, I wrote a white paper on how the GDPR applies to personalization algorithms and recommended changes to bring a company into compliance.

This ePortfolio centers on one artifact, DoveInventory, a Kotlin and Jetpack Compose mobile inventory app I originally built for CS-360. Before making any changes, I recorded a code review that walked through the existing code and the planned enhancements for all three categories. For software design and engineering, I rebuilt the Auth feature to follow the same repository and user case pattern as the rest of the app and finished the registration flow. For algorithms and data structures, I expanded the item search into a multi-criteria filter that uses category data already stored on each item. For databases, I moved that filtering into a parameterized room query, so the databases do the filtering. Together, the three enhancements show one application improved at the architecture level, the logic level, and the data level. The narratives explain each enhancement in detail.
